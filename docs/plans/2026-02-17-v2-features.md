# Lemonade v2.0 Features Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add 7 major features to Lemonade Password Manager: Trash, Password History, Reused Password Detection, Custom Fields, Secure Notes, TOTP Authenticator, and Emergency Access.

**Architecture:** Each feature follows the existing pattern: Cloud Functions (CommonJS, Node 20) for server-side logic with AES-256-GCM encryption, Pinia stores for state, Vue 3 composables for business logic, and Quasar components for UI. ## Phase 1: Data Safety (v1.1.0)

### Task 1: Trash / Soft Delete - Cloud Functions

**Context:** Currently `deletePasswordEntry` does a hard delete via `db.collection('password_entries').doc(entryId).delete()`. We need to convert this to a soft delete that sets a `deletedAt` timestamp, then add functions to restore and permanently delete.

**Files:**
- Modify: `functions/index.js`

**Step 1: Modify deletePasswordEntry to soft delete**

In `deletePasswordEntry` (callable) and `deletePasswordEntryHttp` (HTTP), replace:
```javascript
await db.collection('password_entries').doc(entryId).delete();
```
With:
```javascript
await db.collection('password_entries').doc(entryId).update({
  deletedAt: admin.firestore.FieldValue.serverTimestamp()
});
```

Update audit log action from `DELETE_PASSWORD_ENTRY` to `SOFT_DELETE_PASSWORD_ENTRY`.

**Step 2: Add restorePasswordEntryHttp Cloud Function**

```javascript
exports.restorePasswordEntryHttp = functions.https.onRequest(
  { secrets: [encryptionKey], cors: true },
  (req, res) => {
    return corsHandler(req, res, async () => {
      const token = req.headers.authorization?.split('Bearer ')[1];
      if (!token) return res.status(401).json({ error: 'Unauthorized' });
      const decoded = await admin.auth().verifyIdToken(token);
      const userId = decoded.uid;
      const { entryId } = req.body;

      if (!entryId) return res.status(400).json({ error: 'entryId required' });
      if (!checkRateLimit(userId, 'restore', 10)) return res.status(429).json({ error: 'Rate limit' });

      const entryDoc = await db.collection('password_entries').doc(entryId).get();
      if (!entryDoc.exists) return res.status(404).json({ error: 'Not found' });
      if (entryDoc.data().userId !== userId) return res.status(403).json({ error: 'Forbidden' });
      if (!entryDoc.data().deletedAt) return res.status(400).json({ error: 'Not in trash' });

      await db.collection('password_entries').doc(entryId).update({
        deletedAt: admin.firestore.FieldValue.delete()
      });

      await createAuditLog(userId, 'RESTORE_PASSWORD_ENTRY', { entryId, title: entryDoc.data().title });
      return res.json({ success: true });
    });
  }
);
```

**Step 3: Add permanentDeletePasswordEntryHttp Cloud Function**

Same pattern as restore but actually deletes: `await db.collection('password_entries').doc(entryId).delete()`. Verify `deletedAt` exists before allowing permanent delete. Audit action: `PERMANENT_DELETE_PASSWORD_ENTRY`.

**Step 4: Add purgeTrashHttp scheduled function**

```javascript
exports.purgeTrash = functions.scheduler.onSchedule(
  { schedule: 'every 24 hours', timeZone: 'UTC' },
  async () => {
    const thirtyDaysAgo = new Date();
    thirtyDaysAgo.setDate(thirtyDaysAgo.getDate() - 30);

    const snapshot = await db.collection('password_entries')
      .where('deletedAt', '<=', admin.firestore.Timestamp.fromDate(thirtyDaysAgo))
      .get();

    const batch = db.batch();
    snapshot.docs.forEach(doc => batch.delete(doc.ref));
    if (!snapshot.empty) await batch.commit();
  }
);
```

**Step 5: Update fetch queries**

In `getPasswordEntriesHttp` and all listing functions, add filter to exclude soft-deleted entries:
```javascript
// Existing query
let query = db.collection('password_entries').where('userId', '==', userId);
// Add: only active entries (no deletedAt field or deletedAt is null)
// Firestore doesn't support "field doesn't exist" directly, so we check on client side
// OR add a field `status: 'active'|'deleted'` instead of relying on deletedAt absence
```

**Important:** Since Firestore can't query "where field doesn't exist", add a `status` field: `'active'` (default) or `'deleted'`. Set `status: 'active'` on all new entries. The soft delete sets `status: 'deleted'` AND `deletedAt: timestamp`. Queries filter by `status == 'active'` or `status == 'deleted'`.

**Step 6: Migration function for existing entries**

Add a one-time callable function `migrateAddStatusField` that sets `status: 'active'` on all existing password_entries that don't have the field. Run once after deploy.

**Context:** When a user updates a password entry and the password field changes, we need to save the previous version to a subcollection. This enables viewing and restoring previous passwords.

In both `updatePasswordEntry` (callable) and `updatePasswordEntryHttp`, BEFORE updating the document, if `updateData.password` exists (password is being changed):

```javascript
if (updateData.password) {
  // Save current version to history before overwriting
  const currentData = entryDoc.data();
  await db.collection('password_entries').doc(entryId)
    .collection('password_history')
    .add({
      password: currentData.password,  // Already encrypted
      changedAt: admin.firestore.FieldValue.serverTimestamp(),
      changedBy: userId
    });

  // Then encrypt and update as before
  updateData.password = encryptPassword(updateData.password, encryptionKey.value());
}
```

**Step 2: Add getPasswordHistoryHttp Cloud Function**

```javascript
exports.getPasswordHistoryHttp = functions.https.onRequest(
  { secrets: [encryptionKey], cors: true },
  (req, res) => {
    return corsHandler(req, res, async () => {
      // Auth check...
      const { entryId } = req.body;

      // Verify ownership
      const entryDoc = await db.collection('password_entries').doc(entryId).get();
      if (!entryDoc.exists || entryDoc.data().userId !== userId) {
        return res.status(403).json({ error: 'Forbidden' });
      }

      const historySnap = await db.collection('password_entries').doc(entryId)
        .collection('password_history')
        .orderBy('changedAt', 'desc')
        .limit(20)
        .get();

      const history = historySnap.docs.map(doc => ({
        id: doc.id,
        password: decryptPassword(doc.data().password, encryptionKey.value()),
        changedAt: doc.data().changedAt?.toDate?.()?.toISOString() || null
      }));

      await createAuditLog(userId, 'VIEW_PASSWORD_HISTORY', { entryId });
      return res.json({ success: true, history });
    });
  }
);
```

## Phase 2: Security Intelligence (v1.2.0)

### Task 5: Reused Password Detection - Cloud Function

**Context:** The app already has breach detection and password age checking. Reused password detection needs to decrypt ALL passwords for a user and find duplicates. This is a server-side operation.

**Files:**
- Modify: `functions/index.js`

**Step 1: Add checkReusedPasswordsHttp Cloud Function**

```javascript
exports.checkReusedPasswordsHttp = functions.https.onRequest(
  { secrets: [encryptionKey], cors: true },
  (req, res) => {
    return corsHandler(req, res, async () => {
      // Auth check...
      const snapshot = await db.collection('password_entries')
        .where('userId', '==', userId)
        .where('status', '==', 'active')
        .get();

      const passwordMap = {};  // decrypted password -> [entryIds]

      snapshot.docs.forEach(doc => {
        const data = doc.data();
        try {
          const decrypted = decryptPassword(data.password, encryptionKey.value());
          if (!passwordMap[decrypted]) passwordMap[decrypted] = [];
          passwordMap[decrypted].push({ id: doc.id, title: data.title });
        } catch (e) {
          // Skip entries that can't be decrypted (legacy format issues)
        }
      });

      // Only return groups with 2+ entries (reused)
      const reusedGroups = Object.values(passwordMap)
        .filter(group => group.length > 1)
        .map(group => group.map(entry => entry.id));

      // Flatten to list of entry IDs that have reused passwords
      const reusedEntryIds = reusedGroups.flat();

      await createAuditLog(userId, 'CHECK_REUSED_PASSWORDS', {
        totalEntries: snapshot.size,
        reusedCount: reusedEntryIds.length
      });

      return res.json({
        success: true,
        reusedEntryIds,
        reusedGroups  // Array of arrays of entry IDs sharing same password
      });
    });
  }
);
```

**Context:** TOTP (Time-based One-Time Password) generates 6-digit codes that rotate every 30 seconds. Users add TOTP by scanning a QR code or entering a secret manually. The secret is stored encrypted alongside the password entry.

**Files:**
- Modify: `functions/package.json` - Add `otplib` dependency
- Modify: `functions/index.js`

**Step 1: Install otplib in functions**

```bash

```

**Step 2: Add TOTP field to password entries**

The `totpSecret` field stores the encrypted TOTP secret. It's part of the existing password_entries document (not a separate collection) since TOTP is always associated with a credential.

**Step 3: Add saveTotpSecretHttp Cloud Function**

```javascript
exports.saveTotpSecretHttp = functions.https.onRequest(
  { secrets: [encryptionKey], cors: true },
  (req, res) => {
    return corsHandler(req, res, async () => {
      // Auth check, rate limiting...
      const { entryId, totpSecret } = req.body;
      // Validate: totpSecret must be base32 string
      // Verify ownership
      // Encrypt and save
      await db.collection('password_entries').doc(entryId).update({
        totpSecret: encryptPassword(totpSecret, encryptionKey.value()),
        updatedAt: admin.firestore.FieldValue.serverTimestamp()
      });
      return res.json({ success: true });
    });
  }
);
```

**Step 4: Add getTotpCodeHttp Cloud Function**

```javascript
const { authenticator } = require('otplib');

exports.getTotpCodeHttp = functions.https.onRequest(
  { secrets: [encryptionKey], cors: true },
  (req, res) => {
    return corsHandler(req, res, async () => {
      // Auth check...
      const { entryId } = req.body;
      // Verify ownership, get entry
      const entryData = entryDoc.data();
      if (!entryData.totpSecret) return res.status(400).json({ error: 'No TOTP configured' });

      const secret = decryptPassword(entryData.totpSecret, encryptionKey.value());
      const code = authenticator.generate(secret);
      const timeRemaining = 30 - (Math.floor(Date.now() / 1000) % 30);

      return res.json({ success: true, code, timeRemaining });
    });
  }
);
```

**Step 5: Add removeTotpSecretHttp Cloud Function**

Removes the `totpSecret` field from the entry.

**Step 6: Modify getPasswordEntryHttp**

When returning a password entry, include `hasTotp: !!entryData.totpSecret` (boolean flag, NOT the secret itself). The actual code is fetched separately via `getTotpCodeHttp`.

```javascript
  trusteeId: string | null,   // Firebase UID (set when trustee has a Lemonade account)
  status: 'invited' | 'active' | 'requesting' | 'approved' | 'denied' | 'revoked',
  waitPeriodDays: number,     // 1, 3, 7, 14, 30
  requestedAt: timestamp | null,
  approvedAt: timestamp | null,
  accessExpiresAt: timestamp | null,  // Access expires 24h after approval
  createdAt: timestamp,
  updatedAt: timestamp
}
```

**Functions to create:**

1. `addEmergencyContactHttp` - Grantor adds a trusted contact by email. Sets status='invited'. If trustee already has a Lemonade account, sets trusteeId.

2. `getEmergencyContactsHttp` - Grantor lists their trusted contacts with status.

3. `getEmergencyGrantorsHttp` - Trustee lists who has granted them emergency access.

4. `requestEmergencyAccessHttp` - Trustee requests access. Sets status='requesting', requestedAt=now. **Trigger notification to grantor** (could be in-app notification stored in Firestore).

5. `approveEmergencyAccessHttp` - Grantor approves immediately. Sets status='approved', approvedAt=now, accessExpiresAt=now+24h.

6. `denyEmergencyAccessHttp` - Grantor denies request. Sets status='active' (back to standby).

7. `revokeEmergencyContactHttp` - Grantor removes trusted contact entirely.

8. `getEmergencyPasswordsHttp` - Trustee retrieves grantor's passwords (read-only, decrypted). Only works if status='approved' AND current time < accessExpiresAt.

9. `autoApproveEmergencyAccess` - Scheduled function (every hour): check `emergency_access` where status='requesting' and `requestedAt + waitPeriodDays` has passed. Auto-approve those.

**Step 1: Implement all 9 functions**

Follow existing patterns: corsHandler, auth check, rate limiting, sanitization, audit logging.
